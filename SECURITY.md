# Security and safety policy

Report security issues in protocol parsing, WebSerial handling, configuration
validation, or release tooling privately to the repository maintainer before
opening a public issue. Include a minimal reproduction, affected commit, and
whether the issue can corrupt configuration or escape the browser sandbox.

Hardware safety defects (wrong polarity, relay isolation, excessive current,
or unsafe external-voltage exposure) should be reported as soon as possible
with the board revision, schematic/PCB files, supply/current limit, measured
rails, and photos. Power the board off before investigating a suspected defect.

This is a work-in-progress project without a guaranteed response-time or a
bug-bounty program. Do not use an unqualified revision on stage.
